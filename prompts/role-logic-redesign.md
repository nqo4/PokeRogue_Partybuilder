# 프롬프트: 포켓몬 "사용 양상" 기반 역할 판정 로직 재작성

> 이 문서는 구현 에이전트에게 그대로 넘기는 작업 지시서다. 아래 "작업 지시"부터 끝까지를 프롬프트로 쓴다.

---

## 작업 지시

너는 포켓로그(PokeRogue) 클래식 파티 자동 추천 서비스의 역할 판정 로직을 다시 설계·구현한다.

지금 로직은 종족값과 "특정 기술을 배우는가"만으로 스위퍼·선공형·막이 등을 나눈다. 이를 다음 구조로 바꾼다.
1. **"이 포켓몬은 보통 어떻게 쓰이는가(사용 양상)"를 먼저 추론한다.**
2. 그 결과로 물리/특수/겸용을 정한다.
3. 공격 특화 / 방어 특화 빌드를 정한다.
4. 파티 안의 역할을 정한다.

### 0. 먼저 읽을 것

**지금 구조**
- `src/lib/classic/candidate.ts`
  - `offenseKind()` / `attackSetStrength()`: 지금의 물리·특수 판정.
    - 높은 능력치 쪽을 기본으로 한다.
    - 반대쪽 "최강 세트"가 `flipRatio`(1.3)배 이상 강하면 뒤집는다.
    - 충전기(`TAG.CHARGING`)는 **아예 빼고 계산**한다.
  - `CandidateBuilder.evaluate()`: 역할 9종 점수를 각각 따로 매긴다.
    - 역할: `fastPhys`, `fastSpec`, `sweeperPhys`, `sweeperSpec`, `spread`, `boss`, `physTank`, `specTank`, `support`
    - 광역기 역할은 `usableList`(겸용이면 양쪽 분류 모두)에서 자속 광역기가 하나라도 있으면 0.7점이다.
    - 역할 판정용 기술 목록(`moveList`)은 레벨업·진화·기억버섯과 해금된 알기술이다. 기술머신은 들어가지 않는다.
  - `pickMoveset()`, `pickNature()`: 주 역할 기준으로 기술 4개와 성격을 고른다.
- `src/config/classic.json`: 모든 기준값과 예외 목록.
  - 예: `hybrid.species`, `moveset.excludeMoves`, `offenseAbilities`, `synergyPairs`, `support.moves`
  - `offenseAbilities`는 지금 **물리/특수 구분 없이** 가산점만 준다.
- `src/lib/classic/party.ts`: `roles[r].score`로 포켓몬마다 포지션 하나를 배정한다.
- `src/lib/dex.ts`: 데이터 형태.
  - `MoveInfo`: type, cat, power, acc, priority, procs, tags
  - `DexSpecies`: stats, abilities, moves의 습득 코드, eggMoves, form
  - `TAG` 상수
- `docs/effect-tags.md`: 기술·특성 효과 태그 설명.
- `reports/hybrid-report.md`: 지금 기준의 겸용 판정 결과. 새 로직 결과와 비교하는 기준표로 쓴다.

**특이한 기술·특성 자료** (처리 방식은 `prompts/`, 전체 목록은 `reports/`)

| 주제 | 처리 방식·대표 예시 | 전체 목록 |
|---|---|---|
| 계산 방식이 특이한 기술 (분류·능력치·위력·고정 데미지·타입 변화·충전기) | `prompts/special-calc-moves.md` | `reports/special-calc-moves.md` |
| 쓰는 포켓몬·상대에 따라 효과가 달라지는 기술 (저주, 일구기, 종·폼 전용 기술 등) | `prompts/conditional-moves.md` | `reports/conditional-moves.md` |
| 공격을 강화하는 특성과 기술 시너지 | `prompts/ability-move-synergy.md` | `reports/ability-move-synergy.md` |

- 전체 목록은 `node scripts/report-move-lists.mjs`로 다시 뽑는다.
- 게임 패치 후에는 리포트를 다시 뽑아서 새 기술·특성이 생겼는지 확인한다.

**데이터 원칙**
- 게임 데이터는 공식 포켓로그 코드에서 뽑은 기존 dex 데이터를 기준으로 한다.
- 데이터 파일(`dex.json`, 스프라이트 등)과 데이터 추출 스크립트는 고치지 않는다.
  - **예외: 포켓몬 무게** (7절). 무게를 추출하는 부분만 추가한다.
- 필요한 정보가 데이터에 없으면 추측하지 않는다. `classic.json`에 설정 항목을 추가하거나 나에게 물어본다.

### 1. 설계 원칙

1. **증거 누적 방식**
   - 물리/특수, 공격/방어 빌드, 역할은 모두 "증거" 점수를 더해서 정한다.
   - 증거 하나(기술 하나, 특성 하나)만으로 결론이 뒤집히지 않게 한다.
2. **기술 출처 가중치**: 같은 기술이라도 어떻게 배우느냐에 따라 "그 포켓몬이 실제로 그걸 쓰도록 설계됐는가"의 증거 강도가 다르다.
   - **알기술 > 레벨업·진화 기술 > 기술머신** 순으로 가중치를 둔다.
   - 알기술은 포켓로그가 그 계열에 일부러 넣어준 기술이라 가장 강한 증거다.
   - 기술머신은 범용이라 거의 모든 포켓몬이 배우므로 가장 약한 증거다 (예: 보스로라의 메테오빔).
   - **"기술 하나로는 뒤집지 않음"이 알기술 우선보다 앞선다.**
     - 낮은 쪽 분류에 쓸 만한 기술이 그것 하나뿐이면, 그 기술만으로 싸워야 해서 사용 난이도가 올라간다.
     - 그래서 알기술이고 특성 시너지가 있어도 기술 하나뿐이면 분류를 뒤집거나 겸용으로 만들지 않는다.
     - 예: 칼라마네로(공격 92 / 특공 68)는 레어 알기술 사이코부스트(특수 140, 자속) + 심술꾸러기 시너지가 있지만, 다른 쓸 만한 특수기가 없으므로 **물리형 유지**.
   - 가중치 값 (`classic.json`에 둔다)

     | 출처 | 배율 |
     |---|---|
     | 알기술 (레어 알기술 포함) | 1.0 |
     | 레벨업·진화·기억버섯 | 0.8 |
     | 기술머신 | 0.4 |

     - 기술 점수는 "위력 × 명중률 × 자속 1.5 × 출처 배율"이다. 충전기 등 다른 할인은 여기에 곱한다.
     - 예: 피존투(공격 80 / 특공 70)는 배율 없이 비교하면 물리 14,400 / 특수 14,700으로 거의 같다. 배율을 넣으면 물리 약 6,000 / 특수 14,700으로 특수형이 확실해진다.
   - **해금 안 된 알기술**
     - 물리/특수 판정("보통 어떻게 쓰이는가")에는 해금과 상관없이 알기술 4개를 모두 넣는다.
     - 기술 4개 추천과 역할 점수에는 해금된 알기술만 넣는다. 해금 안 된 기술은 이번 판에서 쓸 수 없기 때문이다.
3. **기술은 데이터상 분류·위력이 아니라 실제 효과로 평가한다.**
   - `prompts/special-calc-moves.md`와 `prompts/conditional-moves.md`의 처리 방식을 따른다.
   - 예: 포톤가이저는 공격이 높은 포켓몬에게 물리기, 바디프레스는 방어로 계산, 저주는 고스트 여부로 효과가 갈림.
4. **시너지는 같은 포켓몬 안에서만 계산한다.**
   - 선택한 특성과 해금된 패시브만 본다.
   - 같은 파티의 다른 포켓몬이 날씨·필드를 만들어 주는 효과는 계산하지 않는다.
5. **판정 결과에는 반드시 이유(`Reason`)를 남긴다.**
   - UI가 이유를 보여주므로 "왜 물리형인지", "왜 방어 특화인지"를 사람이 읽을 수 있는 문장으로 만든다.
   - 근거가 된 기술·특성 fid도 함께 남긴다.
6. **모든 기준값·배율·예외는 `classic.json`에 둔다.**
   - 코드에 숫자를 박지 않는다.
   - 각 블록에 `_설명`을 단다 (기존 형식 유지).

### 2. 물리/특수/겸용 판정 (공격 분류)

분류마다(물리·특수) 아래 증거를 더해 **분류 점수**를 만들고 비교한다.

| 증거 | 설명 |
|---|---|
| 능력치 | 공격 vs 특공. 기본 점수의 바탕. 비율 차이가 클수록 강하게 |
| 자속 공격기 | 위력×명중×자속, 출처 가중치 적용. 가장 센 자속기 1~2개 위주 |
| 비자속 커버기 | 약하게 반영 |
| 랭크업 기술 | 그 분류의 공격 능력치를 확실히 올리는 기술 (칼춤·용의춤·나쁜음모·명상·나비춤 등). 큰 가산점. 고스트가 아닌 포켓몬의 저주는 공격 랭크업으로 본다 |
| 특성·패시브 시너지 | 3절 참고 |
| 메가진화·폼 변화 | 폼의 분류가 다르면 겸용 후보 (지금 로직 유지) |

**기본 규칙**
- **고위력 자속기 하나만으로 겸용이 되지 않는다.**
  - 보스로라(물리형)가 위력 120 자속 특수기 메테오빔을 배워도 특수형·겸용이 아니다.
  - 겸용은 낮은 쪽 분류에도 **독립된 증거가 여러 개** 있을 때만 인정한다 (능력치 + 쓸 만한 기술 여러 개 + 랭크업 또는 시너지 특성).
- 능력치가 같으면 기술·특성 증거가 강한 쪽으로 정한다. 지금 로직과 같은 결과가 나와야 한다 (뮤·지라치 → 특수).
- 예외 목록(`hybrid.species`: 망나뇽·니드킹·니드퀸·킹드라·루기아)은 계속 지원한다.
- "이 포켓몬은 무조건 물리/특수"로 고정하는 목록(`forceCategory`)도 추가한다.
  - **목록 내용은 내가 직접 정한다.** 에이전트는 이 목록에 포켓몬을 넣지 않는다.
  - 에이전트는 비교 리포트에서 "판정이 어색해 보이는 포켓몬" 후보를 이유와 함께 정리해서 보여준다.
  - 내가 확인하고 알려준 포켓몬만 넣는다. `hybrid.species`에 새로 추가할 때도 같다.

**특이한 기술 처리** (자세한 내용은 `prompts/special-calc-moves.md`)
- **포톤가이저**: 공격 > 특공이면 **물리 자속기**로 계산한다 (솔가레오·메가뮤츠X·메가요가램).
- **셸암즈**: 분류 증거에서는 중립으로 둔다.
- **테라버스트·테라클러스터**: 테라스탈 조건부라 분류 판정에서 제외하거나 크게 할인한다.
- **바디프레스·속임수**: 사용자 공격을 쓰지 않으므로 **물리형 증거에서 뺀다**.
- **위력이 바뀌는 기술**: dex 위력을 그대로 쓰지 않는다.
  - 분화·해수스파우팅·드래곤에너지는 할인한다.
  - 어시스트파워·기어오르기는 랭크업 기술이 있으면 높게 본다.
  - 무게로 위력이 정해지는 기술은 7절 방식으로 계산한다.
  - 위력이 없는(`-1`) 친밀도 기술 등은 제외한다.
- **잠재파워**: 거의 쓰지 않는 기술이지만, 쓸 가능성이 있으면 정확하게 평가한다.
  - 보유 포켓몬은 세이브의 개체치로 기술 타입을 계산한다 (`HiddenPowerTypeAttr`와 같은 공식).
  - 계산한 타입으로 자속·커버 기술로 평가한다. 위력이 60(테크니션이면 90)이라 점수는 낮게 나온다.
  - 개체치가 없는 도감 상세에서는 타입을 정할 수 없으므로 평가하지 않는다.
- **고정 데미지 기술**: 제외한다.

**충전기 할인**
- 솔라빔·불새·메테오빔 같은 충전기(`TAG.CHARGING`)는 첫 턴에 충전하는 대신 위력이 높게 잡혀 있다.
- 그래서 일반 기술보다 증거 비중을 낮춘다. 지금처럼 아예 빼지 말고, 설정 가능한 배율로 할인한다.
- 할인 정도는 충전기 종류별로 다르게 한다 (`prompts/special-calc-moves.md` 7절).
  - 충전만 하는 기술: 할인
  - 충전하면서 능력치가 오르는 기술(로켓박치기·메테오빔·일렉트로빔): 덜 할인하고, 오르는 능력치를 랭크업으로 가산
  - 숨는 기술(공중날기·구멍파기 등): 덜 할인
- 예: 피존투는 레벨업 기술·알기술이 특수 쪽에 몰려 있다. 그래서 자속 충전형 물리 고위력기 불새를 배울 수 있다는 이유만으로 물리형이 되면 안 된다.

**충전을 없애는 특성·패시브**
- 충전 단점을 없애는 특성·패시브가 있으면 충전기를 일반 기술과 똑같이, 또는 그보다 높게 본다.
  - 예: 메가리자몽Y는 특성 가뭄으로 맑음 상태에서 솔라빔 충전 턴이 없어진다. 그래서 솔라빔을 일반 기술로(또는 시너지 가산점까지) 평가한다.
  - 이 예시는 "충전기 × 특성 시너지"를 보여주는 것이고, 메가리자몽Y의 특수형 판정 근거 자체는 아니다.
- 충전 생략 조건: 쾌청이면 솔라빔·솔라블레이드, 비면 일렉트로빔.
  - 쾌청을 만드는 특성: 가뭄·끝의대지·진홍빛고동
  - 비를 만드는 특성: 잔비·시작의바다
- 이 관계는 `classic.json`에 데이터로 둔다.
  - 예: `chargeSkip: { "가뭄": ["솔라빔", "솔라블레이드"], "잔비": ["일렉트로빔"], ... }`
- 같은 조건이면 `moveset.excludeMoves`에 있는 솔라빔 등도 기술 추천에서 빼지 않는다.

### 3. 특성·패시브와 분류 시너지

자세한 로직과 특성 분류표는 `prompts/ability-move-synergy.md`를 따른다. 핵심은 이렇다.

- **특성을 "물리 특성 / 특수 특성"으로 고정하지 않는다.**
  - 그 포켓몬이 배우는 기술 중 특성 조건에 맞는 기술에 특성 배율을 곱한다.
  - 그 다음 물리·특수 기대값을 각각 다시 계산한다.
  - 예: 예리함은 물리 베는 기술 28개와 특수 4개(에어커터·에어슬래시·신비의칼·타키온커터)를 함께 강화한다.
- **물리·특수 둘 다 강화하는 특성은 양쪽에 모두 적용한다.**
  - 양쪽에 같은 배율이면 결과가 유지될 수 있다 (라이츄 + 트랜지스터 → 겸용 유지).
  - 강화되는 기술이 한쪽에 몰리면 그쪽으로 기운다 (메가폭타 + 우격다짐 → 특수 강화).
- **스킨류는 바뀐 타입으로 자속을 다시 계산한다.**
  - 예: 메가망나뇽 + 스카이스킨 → 신속·하이퍼보이스가 비행 자속이 된다.
- **낮은 쪽 분류가 특성·패시브 시너지로 기대값이 높으면 낮은 쪽을 고른다.**
  - 예: 특수형인데 "단단한발톱" 같은 물리 기반 특성을 가진 경우, 특성 보정을 넣은 물리 기대값이 특수 기대값보다 높으면 물리형.
  - 능력치 자체를 바꾸는 특성(천하장사·순수한힘 등)도 같은 방식이다 (메가아쿠스타·마릴리 → 물리).
  - 비교는 "능력치 × 최강 세트 위력 × 특성 배율"처럼 같은 척도로 한다.
- **조건이 붙은 특성은 조건을 만족하기 쉬운 정도에 따라 할인한다.**
  - 조건 예: 상태이상(근성·독폭주·열폭주), HP 1/3 이하(맹화 등), 날씨(선파워 등)
  - 날씨·필드 조건은 본인 특성·패시브로 만들 때만 그대로 인정한다.
- **위력 강화가 아닌 특성은 분류 판정에 쓰지 않는다.**
  - 보이지않는주먹·관통드릴: 지키기를 뚫는 효과이고 데미지는 1/4로 줄어든다.
  - 투쟁심·색안경 등 분류와 상관없는 조건의 특성.
- **해금 상태**
  - 해금되지 않은 특성·패시브는 실제 보유 상태(`owned.abilities`, `owned.passive.unlocked`) 기준으로 계산한다.
  - 도감 상세(보유 정보 없음)에서는 "해금하면" 기준으로 두 결과를 모두 보여줄 수 있게 한다.

### 4. 광역기(다대다) 역할

- 광역기 역할은 **주 분류의 광역기만** 본다.
  - 예: 강챙이는 자속 특수 광역기 파도타기를 배우지만 물리형 딜러이므로, 그것만으로 광역기 역할을 주지 않는다.
- 겸용 포켓몬은 기준이 낮은 쪽(부 분류)의 광역기도 검토할 수 있다.
  - 부 분류의 능력치와 기술 기대값이 일정 수준 이상일 때만 인정한다.
  - 주 분류 광역기보다 낮은 점수를 준다.
- 스킨류로 타입이 바뀐 광역기는 바뀐 타입으로 자속을 계산한다 (메가망나뇽의 하이퍼보이스).
- **싱크로노이즈는 광역기 판정에서 뺀다.** 나와 타입이 같은 상대에게만 맞기 때문이다.
- 드래곤에너지처럼 HP에 따라 위력이 줄어드는 광역기는 할인한다.

### 5. 공격 특화 / 방어 특화 빌드 판정 (신규)

포켓몬마다 "공격 특화 빌드"와 "방어 특화 빌드" 중 어느 쪽을 추천할지 정한다.
결과는 `buildFocus: "offense" | "defense"`(필요하면 `"balanced"`)와 이유로 남긴다.

| 공격 쪽 증거 | 방어 쪽 증거 |
|---|---|
| 주 분류 능력치 | HP×방어 / HP×특방 |
| 스피드 구간 | 회복기 |
| 공격 랭크업기 | 회복 특성 (재생력 등) |
| 선공기 | 받는 피해를 줄이는 특성 (`abilityEffects.json`, `tank.physAbilities`/`specAbilities`) |
| 화력 특성 | 방어 랭크업기 (풀 타입의 플라워가드 포함) |
| 스윕 시너지 | 상태이상·방해 기술 (고스트의 저주, 독 타입의 맹독 포함) |
| | **방어 능력치로 싸우는 공격기**: 바디프레스(방어로 계산), 속임수(상대 공격으로 계산) |

- 공격 능력치가 높아도 내구와 회복 수단이 압도적이면 방어 특화가 맞을 수 있다.
- 반대로 내구가 좋아도 강력한 랭크업 + 화력이 있으면 공격 특화가 맞다.
- 둘 중 하나로 정하되, 차이가 작으면 둘 다 후보로 남긴다.
- 바디프레스 + 방어 랭크업(철벽 등)이 있으면 방어 특화 빌드에 큰 가산점을 준다. 방어를 올릴수록 화력도 오르기 때문이다.
- 빌드 결과에 맞춰 성격(`pickNature`), 특성(지금의 `AbilityFocus` 재평가), 기술 4개(`pickMoveset`)를 고른다.
  - 방어 특화면 방어/특방 중 더 의미 있는 쪽을 올리는 성격을 고른다.
  - 바디프레스가 주력기면 방어를 올리는 성격을 고른다.

### 6. 역할 점수

- 9개 역할 이름과 `Candidate.roles: Record<Role, RoleResult>` 형태는 그대로 둔다.
- 각 역할 점수는 앞에서 정한 **사용 양상**(분류 + 빌드 방향)을 먼저 반영한다.
  - 예: 방어 특화로 판정된 포켓몬은 스위퍼 점수를 깎고 막이·서포터 점수를 올린다.
  - 주 분류가 아닌 쪽 공격 역할은 겸용이 아니면 0점이다.
- **방어 특화 + 방해 기술이 많으면 막이와 서포터 역할을 함께 배정한다.**
  - "방해 기술이 많다"의 기준은 **3개 이상**이다. 값은 `classic.json`에 둔다.
  - 세는 기술: 레벨업·알기술로 배우는 `support.moves` 목록 기술. 기술머신은 세지 않는다.
  - 예: 야도란(저주·하품·치유파동), 딩루(날려버리기·저주·도발), 프리져(리플렉터·순풍·오로라베일), 쏘콘(리플렉터·저주·독압정) → 막이 + 서포터
  - 예: 블래키는 내구가 좋지만 방해 기술이 0개 → 막이만
  - 예: 해피너스는 방해 기술이 2개(빛의장막·치유파동)라 막이만
  - 지금 `party.ts`는 포켓몬마다 포지션을 하나만 준다. 보조 포지션(서포터)도 파티 평가(`supportInParty` 등)에 반영되도록 배정 방식을 확장한다. 바꾸는 범위는 설계 단계에서 확인받는다.
- **타입에 따라 효과가 바뀌는 기술** (`prompts/conditional-moves.md`)
  - **저주**: 고스트 타입이면 서포터 가산점. 고스트가 아니면 공격·방어 랭크업으로 보고 물리 스위퍼·물리막이에 반영하며, 선공형에는 넣지 않는다. 그래서 저주는 `support.moves` 목록에서 빼고 코드에서 타입으로 나눈다.
  - **맹독**: 독 타입이면 서포터 가산점을 준다.
  - **일구기·플라워가드**: 풀 타입일 때만 랭크업으로 본다.
  - **종·폼 전용 기술** (심판의뭉치·오라휠·레이징불 등): 해당 포켓몬·폼일 때만 바뀐 타입으로 계산한다.
- 새로 필요한 판정 결과(분류 점수, 빌드 방향, 근거)는 `Candidate`에 필드로 추가한다.
  - 예: `usage: { category: { stat, hybrid, scores: { atk, spa }, reasons }, build: { focus, reasons }, secondaryRoles }`

### 7. 포켓몬 무게 (신규)

무게에 따라 위력이 바뀌는 기술과 무게를 바꾸는 특성·기술이 있다. 무게 데이터를 추가해서 기술·특성 추천과 역할 판정에 쓴다.

**데이터 추가**
- 포켓로그 코드의 종·폼 데이터에 무게가 있다 (`src/data/pokemon-species.ts`의 `weight`, 폼마다 `forms[i].weight`).
- 실제 무게 계산은 `src/field/pokemon.ts`의 `getWeight()`를 따른다 (폼 무게 → 바디퍼지 감소 → 특성 배율, 최소 0.1kg).
- 추출 스크립트(`scripts/official-export/dex.test.ts`)에 종·폼별 `weight`(kg) 필드만 추가한다. 다른 필드는 건드리지 않는다.
- `DexSpecies` 타입에 `weight`를 추가하고, 추출 테스트에 무게 확인을 넣는다.
- 추출을 다시 돌려 `dex.json`이 바뀌는 범위가 무게 필드뿐인지 확인하고 보여준다.

**무게와 관련된 게임 요소**

| 종류 | 이름 | 효과 (코드) |
|---|---|---|
| 기술 | 헤비봄버, 히트스탬프 | 내 무게 ÷ 상대 무게가 클수록 강함 (`CompareWeightPowerAttr`) |
| 기술 | 안다리걸기, 풀묶기 | 상대가 무거울수록 강함 (`WeightPowerAttr`) |
| 기술 | 바디퍼지 | 스피드 +2, 내 무게 -100kg |
| 특성 | 헤비메탈 | 내 무게 ×2 (보스로라·동탁군·대왕끼리동) |
| 특성 | 라이트메탈 | 내 무게 ×0.5 (핫삼·메타그로스·레지스틸) |

**로직**
1. **헤비봄버·히트스탬프**
   - 내 실제 무게(헤비메탈·라이트메탈 반영)로 위력을 추정한다.
   - 상대 무게는 알 수 없으므로 기준 상대 무게를 `classic.json`에 둔다 (예: 최종진화 포켓몬 무게의 중앙값). 기준값을 정하는 방법은 설계 단계에서 확인받는다.
   - 무거운 포켓몬은 고위력 자속기로 평가한다 (예: 보스로라 + 헤비메탈 + 헤비봄버).
2. **안다리걸기·풀묶기**
   - 상대 무게에 따라 달라지므로 기준 상대 무게로 추정하고 할인한다.
3. **특성 선택**
   - 헤비메탈은 헤비봄버·히트스탬프를 배우면 화력 특성으로 가산한다.
   - 라이트메탈은 반대로 내 헤비봄버·히트스탬프 위력을 깎는다.
   - 받는 쪽에서는 효과가 엇갈린다. 상대의 안다리걸기·풀묶기는 약해지지만, 상대의 헤비봄버·히트스탬프는 오히려 강해진다 (내가 가벼울수록 위력이 오름).
   - 헤비메탈·라이트메탈은 상대의 틀깨기·터보블레이즈·테라볼티지·균사의힘과 메테오드라이브·섀도레이·포톤가이저에 무시된다.
   - 헤비봄버를 쓸 포켓몬이 라이트메탈을 숨겨진 특성으로 가졌으면(레지스틸·메타그로스), 다른 특성을 추천한다.
4. **기술 추천 충돌**
   - 바디퍼지는 무게를 줄이므로 헤비봄버·히트스탬프와 함께 추천하지 않는다.
   - 바디퍼지는 스피드 +2 랭크업 기술로 평가한다.
5. 판정 이유에 무게 근거를 남긴다 (예: "무게 ○○kg, 헤비메탈 → 헤비봄버 최대 위력").

   | 메타그로스 또는 레지스틸 | 라이트메탈이면 헤비봄버 위력이 낮게 평가됨 | 라이트메탈 배율 반영 |
   | 쏘콘 또는 강철톤 | 바디퍼지와 헤비봄버를 함께 추천하지 않음 | 기술 추천 충돌 |
   | 보스로라 또는 강철톤 | 바디프레스를 방어 특화 빌드의 공격 수단으로 평가 | 바디프레스가 물리형 증거로 쓰이지 않음 |

2. 전체 평가 형태에 대해 지금 로직과 새 로직의 결과를 비교하는 리포트를 `reports/`에 만든다 (`hybrid-report.md` 형식 참고).
   - 분류가 바뀐 포켓몬
   - 겸용 판정이 바뀐 포켓몬
   - 광역기 역할이 사라지거나 생긴 포켓몬
   - 빌드 방향 분포
   - 막이 + 서포터를 함께 받은 포켓몬
   - 바뀐 항목마다 이유를 적는다.
3. 리포트를 보고 어색한 결과(대표적인 사용법과 다른 판정)를 목록으로 정리해서 보여준다. 기준값 조정은 내 확인을 받은 뒤 한다.
4. `npm test`와 타입 검사가 통과해야 한다.

### 9. 작업 방식

- 구현 전에 설계를 먼저 짧게 정리해서 확인받는다.
  - 점수 공식
  - 새 설정 항목
  - `Candidate`에 추가할 필드
  - `party.ts` 변경 범위
  - 무게 추출 방법과 기준 상대 무게
- 코드 주석과 커밋 메시지는 영어, 나에게 하는 설명은 한국어로 한다.
- 커밋·배포는 내가 요청할 때만 한다.

## (작성자 메모) 정해진 것과 남은 것

**정해진 것**
- 기술 출처 비중: 알기술 > 레벨업 > 기술머신
- 시너지는 본인 특성·패시브만 계산 (파티의 다른 포켓몬 날씨·필드는 무시)
- 방어 특화라도 방해 기술이 많으면 막이 + 서포터 역할을 함께 배정
- 특성은 물리/특수로 고정하지 않고, 강화되는 기술로 판정 (양쪽 다 적용될 수 있음)
- 저주는 고스트 여부로 서포터 / 랭크업을 나눔
- 계산·효과가 특이한 기술은 `prompts/` 문서 3개의 처리 방식을 따름
- "기술 하나로는 뒤집지 않음"이 알기술 우선보다 앞섬 (칼라마네로 → 물리 유지)
- 방해 기술 기준값: 3개 이상
- 포켓몬 무게 데이터를 추출해서 무게 기술·헤비메탈·라이트메탈·바디퍼지를 평가
- 잠재파워는 세이브 개체치로 타입을 계산해서 평가
- 수동 고정 목록(`forceCategory` 등)은 사용자가 직접 보고 정함. 에이전트는 후보만 제안
- 출처 가중치: 알기술 1.0 / 레벨업 0.8 / 기술머신 0.4 (A안)
- 해금 안 된 알기술: 물리/특수 판정에만 넣고, 기술 추천·역할 점수에는 넣지 않음
